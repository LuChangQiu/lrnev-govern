## 二、关键裁决：路径 2（payload 生成侧注入 + 渲染器投影）**符合 08-00 单源原则**

**裁决**：✅ **接受路径 2**。

**理由**：
1. T-004 原文："content 必须从 canonical payload 渲染"——渲染器投影 ai_followup 正是 canonical payload 投影，**比渲染器侧 import 更符合 T-004 本意**（渲染器不应重复引入业务文本，避免双源）
2. 常量单源性**未破坏**：USER_DECISION_PRIORITY_CLAUSE / SPEC_CREATION_SUCCESS_FOLLOWUP / SPEC_REWRITE_GUIDANCE 的**唯一文本源**仍是 guidance-semantics.ts + SpecManager/SpecGuidance 注入点——渲染器不产生第二份文本
3. 上轮核心目标是"**禁止 paraphrase**"——已达成（grep 无硬编码近似文本；测试断言常量原文片段"不是强制规则"/"VV+1"/"【事实】"/"不得擅自撤销"全部通过）
4. assess-goal 直接 import 是**额外保险**（该常量不在 ai_followup 中，必须渲染器侧引用）——两种路径并存是合理的

**grep 验证口径更新**：验收改为"渲染器不得包含 guidance 文本的硬编码 paraphrase（注释除外）"，而非"必须 import"。
