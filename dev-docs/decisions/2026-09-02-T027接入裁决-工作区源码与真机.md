Claude Phase 1 基建方案中"三客户端 MCP 配置"需澄清两点：

1. MCP 接入走 **npm 已发布版** lrnev（现状 `~/.claude.json` 中 `"lrnev": {"command": "lrnev-mcp"}`，全局 lrnev@2.3.0），还是**工作区当前代码**？
2. clean sessions 是**自动化测试**（模拟/回放）还是**真机测试**（真实客户端 + 真实模型）？

## 裁决 1：MCP 接入必须指向工作区源码，且支持按 SHA 切换

**不得走已发布版**。理由（对照 T-027 验收标准）：

1. **被测行为不在发布版**：T-027 证据要求 `decision_context`（真实 MCP 拦截记录）等字段，发布版无此参数/字段，接入后 E-01~E-11 无法表达 explicit/preferred/unspecified，全部退化为无效观测。
2. **双 SHA 对照无法成立**：SHA A=`45a86e15c896c446a41e48324e646d32c27fb76a`（B0-s 基线）与 SHA B（08-00 迁移后文本，当前取 `6383e99`，须在 05-00 合入前执行）是 git 历史两点；发布版是单一快照。
3. **文本变量在 git 历史里**：盲测观测的是"02-00 冻结文本 vs 08-00 迁移文本"对真实 AI 行为的影响，只有 checkout 历史 SHA 才能提供对应服务端文本。

**接入形态（实施要求）**：

- 单一 wrapper 入口脚本（工作区 `scripts/t027/` 下），三个客户端 MCP 配置的 command 均指向它；wrapper 读指针文件（如 `.t027-target-sha`）决定从哪个 **git worktree** 启动 `tsx src/mcp/server.ts`。
- SHA A / SHA B 各一个独立 worktree，不污染主工作区（05-00 开发进行中）。
- **切换 SHA = 改写指针文件**，客户端配置零改动。
- 用独立 MCP 实例名（如 `lrnev-t027`）接入；**不动**全局 `~/.claude.json` 中日常发布版配置（`lrnev`）。
- 冒烟验证（Phase 1 必做，否则后续全白跑）：
  - SHA A 历史提交能否按当时依赖锁文件正常启动（worktree + npm ci 或复用 node_modules 可行性）；
  - 服务端启动后工具清单/信封行为与预期 SHA 一致（记录 tools/initialize 摘要入证据）。

## 裁决 2：真机测试（真实客户端 + 真实模型 + 真实 MCP 链路），非模拟/回放

依据（任务原文）：

- tasks.md L835-837："真实 AI 行为观测，非 fixture 预期回放""真实 MCP 拦截记录，非模拟值""真实回传，非 null"。
- B2a manifest 诚实性声明："代码路径推断值，非真实客户端观测，真实验证归 T-027"——B0~B2b 全为推断/套件产出，T-027 是**首次真实行为观测**。
- D-05（design.md L69-71）：CI 模拟/回放仅验证"解析、记录、矩阵判定"机制；**发布前用真实 Claude Code/Codex 等主力客户端执行 5 轮 clean-session 测试**。

**执行形态（两层）**：

1. **主体：harness 驱动的真机**。用各客户端 CLI 非交互模式（`claude -p` / `codex exec` / `opencode run`）在全新独立会话中注入场景用户原话；每次调用即天然 clean session；5 次重复 = harness 循环。harness 只做：fixture 工作区准备、clean session 启动、会话产物录制（工具调用/服务端日志/最终动作/decision_context 拦截）。**不得用 mock MCP client 直调服务端冒充真机**。
2. **抽验：每客户端 ≥1 个 explicit 场景（E-01/E-02）由人在交互模式真跑 1-2 次**，验证 headless 与交互模式行为一致（防 headless 走不同工具策略）。

**盲测落地（F-03）**：场景 prompt 文件只含用户原话与工作区上下文，**不含 expectedAction / evidenceFields**；期望对照脚本在会话结束后才读 fixture。执行者（harness 或人）全程不可见期望答案。

**Phase 1 冒烟验证（必做）**：

- 三客户端 headless 模式是否启用 MCP 工具（已知坑：老版本 `claude -p` 工具受限）；若受限该客户端退回交互式并记录。
- headless 冒烟：每客户端 1 个 explicit 场景（E-01）跑 1 次，确认工具可调用、信封/拦截记录可采集，再放量 5 轮。
