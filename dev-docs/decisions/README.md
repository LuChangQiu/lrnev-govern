# dev-docs/decisions/ — 审定决策档案（入库镜像层）

## 本目录定位

本目录是 `ai-discussions/结果/` 中 **DeepSeek 审查方审定终稿**（裁决 / 汇总 / 规格）的**入库镜像**。
凡 CHANGELOG.md、ADR、dev-docs 报告引用的数据与判定声称（如"B4 归档率 4/5→0/5"、四层分级迁移裁决、T006 字段裁决等），其可核验依据均以本目录文件为准——GitHub 可见、可链接、可追溯。

首批入库：**2026-09-04 ~ 2026-09-07 发布战役决策档案共 17 份**（DeepSeek 裁决 2026-09-07：审定层镜像入库以保证 GitHub 上发布声称可核验）。

补批入库：**2026-08-28 ~ 2026-09-03 早期审定定稿共 56 份**（补齐 08-26 ~ 09-03 缺口期：3.0.0 早期声称——如 ADR-01/02/03 的 P0 输入、02-00/03-00/04-00 复审通过、M1 合入门禁、B2a/B2b 证据复审通过、放量证据契约与 R1 试点规格等——的审定依据此前仅存本机 ai-discussions；区间内最早审定文件为 08-28，08-26/08-27 无文件）。批次纪律同首批：内容原样、同名不覆盖、SHA256 校验；镜像共 **73 份**（17 首批 + 56 补批）。

2026-09 收尾分流：补批镜像中**纯逐任务"复审通过"过程背书（08-28 ~ 09-03 共 36 份）已归档至 `dev-docs/archive/decisions/`**（GitHub 仍在、可核验；逐任务复审结果是过程背书而非审定决策档案，见 `dev-docs/archive/README.md`）。分流后本目录留存 **37 份** = 首批 17 + 补批留存 20；镜像累计仍 73 份（37 留存 + 36 归档）。

## 分层结构

| 层 | 位置 | 内容 | GitHub |
| --- | --- | --- | --- |
| 讨论区本体 | `ai-discussions/` | 会话日志、复审意见轮次、多客户端意见、过程记录 | 不上 GitHub（`.gitignore` 忽略 `/ai-discussions/`） |
| 审定档案（本目录） | `dev-docs/decisions/` | DeepSeek 审查方裁决 / 汇总 / 规格终稿 | **入库**，GitHub 可核验 |
| 复审通过背书（归档） | `dev-docs/archive/decisions/` | 纯逐任务"复审通过"过程背书（历史） | **入库**，GitHub 可核验 |

- **ai-discussions/ 本体 = 本机讨论区**：会话日志、复审意见轮次（211 份结果文档中大半为此类）、多客户端（DeepSeek / ClaudeCode / Codex）意见与过程记录。仅本机留存，不进入 GitHub。
- **dev-docs/decisions/ = 审定决策档案**：DeepSeek 审查方定稿（裁决 / 汇总 / 执行规格）的入库镜像。GitHub 发布声称（CHANGELOG / ADR / 报告）的引用依据在此，不因 ai-discussions 断链而不可核验。
- **dev-docs/archive/decisions/ = 复审通过背书归档**：文件名含"复审通过"的逐任务复审结果（过程背书，非裁决/汇总/规格终稿），随 2026-09 收尾整体移出本目录归档；历史原样保存，引用用 `dev-docs/archive/decisions/<文件名>`。

原则一句话：**讨论区保持本机，审定层镜像入库，过程背书归档分流**。

## 维护规则

1. 新的审定终稿（DeepSeek 审查方**定稿**：裁决 / 通过 / 汇总 / 规格）发布时，镜像一份到本目录，文件名 = 源文件名去掉 `DeepSeek-` 作者前缀（`YYYY-MM-DD-<主题>-<类型>.md`；作者信息见内容与下方清单）。
2. 意见轮次（复审意见 / 审查意见 / 过程记录 / 多客户端草案）**不入库**，留在 ai-discussions/ 本机作为过程链。
3. 镜像必须**内容原样**：`copy` 不改内容、不改文件名；复制后建议以哈希（SHA256）校验一致性。
4. 本目录内文档**只增不改**：审定层是既定决策的档案快照；如需修订，新裁决另立新文件，不覆盖旧档。
5. 每批镜像入库应在 commit message 中标注批次区间（如 `docs(decisions): ... 09-04~09-07 ...`）以便追溯。
6. **文件名含"复审通过"的逐任务背书不入本目录**：直接随归档批次放 `dev-docs/archive/decisions/`（本目录清单不含该类；08-28 ~ 09-03 的 36 份已整体归档）。

## 引用约定

- tracked 文档（CHANGELOG.md、`.lrnev/decisions/adr/`、dev-docs 报告等）引用审定依据时，**指向本目录路径**（`dev-docs/decisions/<文件名>`），**不指向 `ai-discussions/` 路径**——后者已 gitignore，GitHub 上断链。
- 引用已归档背书（复审通过类）时指向 **`dev-docs/archive/decisions/<文件名>`**（归档原则同 archive/：原样保存、内部引用不保证）。
- 既有文档中"裁决文档仅本机 `ai-discussions/结果/...`，GitHub 无镜像"类标注（如 `.gitignore` 注释）随本镜像层建立已过时，由各文档维护者在改动该文件时顺带改为指向本目录镜像（本次未改，见批次纪律）。
