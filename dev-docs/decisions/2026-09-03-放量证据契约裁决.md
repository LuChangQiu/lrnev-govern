## 裁决

| # | 问题 | 裁决 |
|---|---|---|
| Q1 | 采集架构 | **A+B 混合，分阶段**。第一阶段（放量第一批可立即启动）：B 的合理部分——content_hash 从**目标 worktree server 源码字节**计算（guidance/instructions 模块在 worktree 内，文件字节即权威，保真成立）；response_version/instructions 原始字节等客户端不可采字段 → 显式 null + `c_class_basis` 注明。第二阶段：**wrapper stdio 代理层**（透传 + 旁路记录 initialize/tools/list/tool structuredContent）列入放量基建并行开发，就绪后启用。不做 C（全 null 放弃） |
| Q2 | stage/sha 命名 | stage=`"T-027"` + `sha_label`（sha-a/sha-b）+ `sha`（40hex）+ baseline_ref 注明 A=45a86e15（B0-s 基线文本）/ B=6383e99（M2+收尾文本）。**不改 D-02 stage 枚举**（B0'~B1' 会造成跨清单混乱） |
| Q3 | decision_context | **采纳**：evidence `decision_context`=null（客户端未传语义）+ `decision_context_sent: false` + 独立 `fixture_context` 存工作区快照。盲测对照用 fixture.expectedDecisionContext 事后再比对，不写入 evidence.decision_context |
| Q4 | failure 双轨 | **采纳并存**：evidence `failure_category`（schema enum 工具级）+ 聚合分析层 `failure_class`（F-04 A-E 观测类，DeepSeek 事后填）。schema enum **补 'test_failure'**（历史产出合规化） |
| Q5 | 字段名 | **以契约为准**（git_sha/mcp_version/model_version/tool_sequence/action_taken 不动）；D-02 文档加别名注释（server_sha=git_sha 等）。反向统一成本高且破坏 B0~B2b 存量 join |
| Q6 | fixture_hash | **统一到 EvidenceCollector 64hex 行为收窄口径**（与 B0~B2b 跨阶段可比）；harness 改造为同口径；存量 8hex 历史 evidence 标注 legacy（不改历史文件） |
| Q7 | schema 治理 | **放量前置（P0）**：修订 evidence-contract.schema.json 容纳会话级扩展（decision_context_sent/guidance_surfaces/clean_session_id/fixture_context/c_class_basis/sha_label 等）；required 口径：decision_context 字段 present 但可 null；**补 validator 脚本**纳入 T-027 新证据校验。存量清单不合规仅标注（统一审查项），不回溯修数据 |
| Q8 | client_version | 三客户端均可行（不限定 claude-code）：client_version 用 CLI 预取版本（`claude --version`/`codex --version`/`opencode --version`）或 init 事件字段（claude_code_version 实测 2.1.228），记录来源；未验证允许 null+原因 |
| Q9 | surface 粒度 | **采纳并存**：`surface_id`（场景主 surface；server instructions=workflow_overview 每 session 真实消费，语义注明）+ `guidance_surfaces[]`（会话级全集，代理层就绪后填充；当前阶段可空数组 + c_class_basis） |
