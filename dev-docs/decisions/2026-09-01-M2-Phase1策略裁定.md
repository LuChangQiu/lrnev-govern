## 二、裁定：方案 A 拒绝，方案 B 采纳

### ❌ 方案 A（toolName 可选 + 未传回退 legacy）——拒绝

**违反 T-004 L66**："回退以受影响工具为粒度，不通过全局开关掩盖局部回归"。

`toolName` 可选 = 未传时**全部静默走 legacy**——这就是"全局开关"：
1. 漏传 toolName 的工具不会报错，静默回退 M1，回归不可见
2. 42 个工具逐个迁移时，漏改的工具无感知——"声称完成实为部分完成"的温床
3. 与 M2 计划"未注册 renderer → legacy 回退"是**两个概念**：前者是调用层静默降级（坏），后者是注册表显式回退（好，设计内）

### ✅ 方案 B（toolName 必填 + 42 个调用逐个传）——采纳

**用户已授权**："实在不行 你就手动挨个去改"。

**关键设计（消除静默）**：
```
1. toMcpToolResult(promise, toolName, legacyRawFormat?) —— toolName 必填（TS 编译强制）
2. 42 个调用逐个传 toolName（手动，用户授权）
3. renderer 注册表：未注册 → legacy（显式回退，与必填不冲突）
   - Phase 1 注册表可为空或仅 error renderer，全部工具显式走 legacy（与 M1 行为等价）
   - Phase 2 起逐批注册 MVC renderer
4. 漏传 toolName → 编译错误（必填参数），不是静默
```

**好处**：编译期保证 42/42 全覆盖；回退是注册表显式行为；Phase 2 迁移是"注册 renderer"而非"改调用"。
