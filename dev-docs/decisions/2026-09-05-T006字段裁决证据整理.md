## 0. TL;DR（裁决前置事实，三句话）

1. **输出侧：实测唯一被消费的 guidance 载体是文本通道（ai_followup.instructions / content），不是结构化 `guidance` 数组。** sha-c 批（918581e，Profile 首次挂载窗口）实测 10 次 spec_create OK 响应挂载了 `guidance=[FACT, RECOMMENDATION]`（20 条结构化项），**380 个录制 jsonl 中没有任何 assistant thinking/text 引用过 profile_version / role / guidance 结构化字段**——结构化数组 = 未来收益假设而非实测消费；且每条 OK 响应多付 ~583 字符（约等于该响应文本的 24.2%）的纯重复 token（B3 对照汇总 §一；转录复算）。
2. **输入侧：decision_context 的真实客户端命中不是 0。** sha-a/b 确实 0 命中（那时 Profile 输入面尚未暴露），但 sha-c（918581e）实测 **claude 4 次命中**（E-06a/b round1 的 spec_create，全部 strength=explicit+direction=new_spec 的**对齐成功场景**，其中 1 次先被负向校验拒绝后自纠成功）。全部 380 录制件中 **0 次命中 mismatch / no_spec / unspecified / preferred / target_ref 完整引用 / reported_user_quote**。**同时发现 04-00 evidence 观测缺口**：这 4 次命中的 evidence .json 仍记 `decision_context_sent=false`（harness 硬编码盲测假设，未按转录回核）——T-006 引用"客户端零使用"必须改为引用转录复算结果，不能引用 evidence 字段本身。
3. **建议初稿总方向**：文本通道（含 ROLE_PREFIX 角色行）全保留（有送达+引用实证）；结构化 guidance 数组、source_ref、enforcement、reported_user_quote 无消费/无失败证据支撑，走"回退挂载或冻结为 experimental + 记录结论"（05-00 验收标准"若字段无改善或客户端忽略，已停止增加字段并记录结论"）；decision_context 的 direction/target_ref/source/strength/summary 输入契约保留（服务端能力测试证据全、真实面窄属采样问题），reported_user_quote 建议回退。
