## 根因定论（三因叠加）

1. **guidance 触发缺口（机制因）**：sha-a 的 E-02 实际消费路径（WORKFLOW_OVERVIEW L1-8/L88-89、工具 description L30-31/L27、spec_get followup、project_status followup）上**零句**把"已有 in-progress spec 下的补充/登记工作"指向 task_create；SPEC_REWRITE_GUIDANCE 仅 completed 触发（E-02 的 A 是 in-progress → spec_get 零 followup）；L125"修改现有需求/设计/任务时直接编辑原文件"**反向背书**直接编辑。
2. **AI 意图→动作映射（认知因）**：模型把"在登录 Spec 里补充用户登录"识别为**内容写作任务**（给占位模板写正文）而非**治理登记任务**——thinking 实录显示"Let me supplement it with comprehensive user login requirements, design, and tasks"（连 tasks.md 都手写 T-001..T-008）。"知道 task_create 存在"（工具列表有）但从未触发映射。
3. **工作区形态 artifact（环境因）**：harness 构建器把 in-progress spec 写成最小占位模板（`## F-01 基础需求/需求描述。`）——**隐性诱导"填充文档"心智**。HEAD 后期改进（08-00 USER_DECISION 优先）不覆盖 E-02 路径——②"快照旧"不成立。

**F-04 记录口径**：E-02 FAIL = A 类候选（explicit reuse 意图下期望机制 task_create(A) 未达成）；AI **未违反 reuse 意图本身**（未新建 B、落位 A 正确）——是"落地机制 ≠ 治理登记"而非"违背用户方向"。判定分两层注明：禁止 spec_create ✅ / 期望 task_create(A) ❌。

## 引导改进设计（从 AI 认知角度：什么引导真正有效）

**原则：引导要在 AI 的决策点出现，条件式优于常驻式，示例优于规则。**

| # | 改进 | 位置 | 为什么有效（AI 认知依据） |
|---|---|---|---|
| G1 | **spec_get followup 条件引导**（spec 存在且非 completed）：【建议】"若用户意图是新增可独立验收的开发增量→用 task_create 在 spec 下登记；若仅修改既有正文→可直接编辑原文件" | sha-a SpecGuidance.ts（05-00 后主工作区） | **最高效决策点**：AI 刚读完 spec、正要决定下一步动作时收到提示——recency 效应下遵循率最高；远胜 WORKFLOW_OVERVIEW 开头泛化流程（长上下文早期信息易丢失） |
| G2 | **task_create description 补触发场景**："何时用"加"在已有 in-progress/ready spec 下登记新增执行项/增量" | tools/index.ts 工具描述 | description 是 AI 工具选择的直接依据；当前全为"创建阶段"语义，AI 在"继续开发"情境不会联想到 |
| G3 | **WORKFLOW_OVERVIEW 边界澄清**：L6"已有特性增量→落位 spec"拆为决策层（落哪个 spec）+ 机制层（登记用 task_create）；消除与 L125"直接编辑原文件"的歧义——改为"**新增需求条款/开发增量走治理登记（task_create）；修改既有文本内容可直接编辑**" | guidance.ts | 消除反向引导：L125 当前为任何编辑行为背书；AI 需要明确"改内容 vs 增登记"的边界 |
| G4 | **示例驱动**：task_create 例子补"用户在已有 spec 说'继续补充登录功能'→ task_create{scene,spec,title}" | description example | AI 对示例的模仿遵循显著强于抽象规则 |
| G5 | **T-027 侧（不影响被测 guidance）**：harness 工作区构建器按场景生成**内容形态真实的 spec**（模拟"已开发"的 spec：requirements 有完整 F 条款而非占位模板）——消除"待填充"诱导 | harness-mvp.mjs 构建器 | 工作区是测试环境非被测文本——AI 看到"内容已完整"后不会触发填充心智，转而正确思考"增量如何登记" |

**生效边界**：G1-G4 属 05-00 Profile/guidance 改进（B3 后主工作区生效；sha-a/sha-b 快照不变——T-027 双 SHA 对照记录"无引导基线"真实行为 = 门禁证据）；G5 可在扩量前做（测试环境改进）。
