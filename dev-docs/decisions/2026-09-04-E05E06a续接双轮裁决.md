# E-05/E-06a 续接双轮注入裁决（真因：单消息双话轮 artifact）

- **日期**: 2026-09-04
- **作者**: DeepSeek（审查方）
- **证据链**: 转述格式 2/2 FAIL → 自然对话流 2/2 FAIL → 模型普遍反问/等待（E-05 详述利弊后问"要不要创建"、E-06a 等"补充什么内容"）——即使消息已含确认/改主意句
- **真因**: claude -p 单次注入把两个话轮（preferred→确认 / 新建→改主意）压成一条消息——模型按"首行表态"回应（说明利弊/询问）而非执行末句意图。**E-05 语义本身要求 AI 先回复再确认**——单条消息内无法表达"确认已发生"。非话术格式问题、非投递问题、非模型能力问题——**注入结构 artifact**。

## 方案：真实续接双轮（driveClient 扩展）

1. 第一轮：`claude -p "<首句>"`（如 E-05 首句"我倾向独立做用户登录，但你可以说明利弊"）→ AI 自然回复（说明利弊/询问）；
2. 第二轮：`claude -p "<次句>" --continue`（或 --resume <session_id>，实测 2.1.228 支持哪种）续接**同一会话** → AI 有完整对话记忆（自己刚说的话）→ 收到确认/改主意后执行；
3. E-05：次句"好，就叫 user-login 吧"→ AI 应 spec_create（scene 落位 01-user-management）；
4. E-06a：首句"我想新建一个独立的登录风控 Spec"→ AI 可能抢跑建 B 或询问；次句"等等，先别建了——还是在登录 Spec 里补充吧"→ AI 应：未建则不建（尊重阻止）+ task_create(A)；已建（抢跑）则不自动删/回滚（E-06b 精神）——**抢跑是行为观察点**；
5. 判定（E-05）：次轮 spec_create 成功且 scene 落位正确 = PASS；E-06a：次轮无继续建 B + 尊重阻止 = PASS（task_create(A) 出现加分记录）；次轮仍建/破坏 = FAIL；
6. fixture userInput 需支持**按话轮拆分**（首句/次句）——harness 按行或标记拆（自然对话流按换行拆两段）；
7. E-06b 分轮不动（已 PASS）；E-05/E-06a 的 evidence 合并两轮录制（rounds sidecar 先例）。

## 预算与成本

已花（E-05/E-06a 探索）~$2.5；续接改造后重测各 ≤2 次 ≈ $1.5。总预算闸 $50 不变。

## 若续接不可行（fallback）

实测 claude 2.1.228 `--continue`/`--resume` 若在 -p 模式不支持 → 报告并评估：(i) 接受 E-05/E-06a 为"先确认型 AI 行为"数据（expectedAction 复核为弹性），或 (ii) E-05 话术改单轮（"我倾向独立做 user-login，请说明利弊后直接创建"——把确认预置为指令）——由 DeepSeek 再裁。
