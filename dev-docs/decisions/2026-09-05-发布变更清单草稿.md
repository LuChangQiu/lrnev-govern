## 7. 版本号建议

**裁决（2026-09-07 用户拍板）：2.3.0 → 3.0.0（major）。** 定案理由：① 整体重构量级（§3 四组新增 + 引导语义体系为架构级变更）；② text 通道行为破坏（§3-B：JSON → 渲染文本，机器解析 text 的接入方需迁移 structuredContent）；③ major 让未来接入方明确需重新对齐。拍板点②（isError 统一 + INTERNAL_ERROR 不泄原文）= 修复性变更，进 CHANGELOG Changed 说明。

理由：
1. **用户可见新增能力多且成体系**：结构化输出双通道 + outputSchema、Guidance Profile v1、
   `decision_context` 可选入参、`--profile core|full` 分层——四个都可独立作为 minor 的 Added。
2. **无协议破坏**：工具无删改（42=42 代码级比对）、inputSchema 只加可选字段、响应为加法
   （structuredContent/guidance/response_version 均新增且 text 通道信息不减）、默认 full 与 2.3.0
   配置零差异；数据文件格式零变化。
3. **不升 major 的理由**：两条行为面变更（text 通道由 JSON 改渲染文本、错误 isError 收严）方向上
   与 v2.x 已声明的"响应信封（ok/data/ai_followup）+ CLI JSON 包装"演进一致，且 v2.1.0 先例同样
   以 minor 承载了 gate check JSON 包装变更并写升级指南。按本项目先例，minor + 显式升级指南即可；
   **若发布讨论判定"text=JSON"属对外承诺的机器契约（如存在解析 text 的正式接入方），则应改判
   major（3.0.0）或推迟 text 变更**——此判定留给用户。
4. 版本号内部一致性：package.json version 现为 2.3.0 未动；发布时按拍板版本同步 package.json、
   CHANGELOG 链接定义段与 docs 内版本引用。
