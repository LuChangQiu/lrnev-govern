# DeepSeek 裁决：3.1 路线——不新增功能项；Verify/Eval 与 git 执法环挂起；战略文档移除

**日期**：2026-09-07（3.0.0 发布当日）
**背景**：3.0.0 发布后收到外部 AI 复审（建议 Verify/Eval 语义验证、SQLite 索引等）；仓库内旧战略文档（PRODUCT-STRATEGY / NEXT-STEPS，v2 时代产物）将"git 执法环"列为第二战略优先级。经与用户多轮讨论，作出以下裁决。

## 裁决 1：3.1 不排期任何新功能

所有候选功能均未通过"真实痛 + 不越界"双门槛。依据：
- lrnev 核心承诺是硬边界：**零模型依赖**（确定性引擎——它说的每个字都来自读文件）、**只引导不强制**、**文件即真相**、**只治理 .lrnev 档案、不读取/锁定/评判代码区**（TaskManager 既有自我约束）。
- 自证先例 T-006：结构化 guidance 挂载"看起来天经地义"，380 个真机录制件零消费 → 回退。规矩由此确立：**先证据后实现**——没有真实损失案例的功能不立项。
- 反证：lrnev 自身的多 Agent 开发语义复审跑在 harness 之外（外部审查者），连自己都不用内建语义验证。

## 裁决 2：逐项拒绝理由（可复用，防重复推演）

| 候选 | 裁决 | 理由 |
|---|---|---|
| Verify/Eval 语义验证进核心 | 拒 | 零模型边界；验证者无限后退（谁验证 Verify Agent）；无需求证据；"看用户原话"不可行——`reported_user_quote` 380 件零命中证明客户端不携带用户原话 |
| completion gate 证据硬拦 | 拒 | 可选 = 零消费（同上先例）；硬拦 = 越界（gate 只判结构不判质量是刻意边界） |
| git 执法环 / 工作树体检 | 挂起（拒当前形态） | 首用噪音（存量接入体验）；引入 git 外部依赖假设（lrnev 至今零外部工具假设）；治理对象从 .lrnev 档案扩张到代码活动（滑坡起点）。若未来真实需求出现，正确形态 = **用户侧扩展点**（hooks 事件机制已提供 `task.update.*` 等，用户自挂 git 检查），lrnev 不主动监控代码区 |
| Searcher 索引 / SQLite | 缓 | 量级未到（治理语料当前毫秒级全扫）；索引 = 缓存层非真相。触发条件：真实项目扫描可感知（>300-500ms）再评估 `.lrnev/cache/` 索引 |
| 长对话遗忘 | 不归 lrnev | Agent 上下文压缩是 harness/客户端职责；常驻提示词模板 workaround 是正确层级（3.0.0 已提供） |
| 意图确认 / checkpoint | 客户端侧 UX | 协议层已给 decision_context（client_asserted）；更强确认属于客户端交互设计 |

## 裁决 3：战略文档移除（2026-09-07）

- `dev-docs/PRODUCT-STRATEGY.md` 与 `dev-docs/NEXT-STEPS.md` **git rm 移除**（非归档）：
  - v2 时代推理产物，3.0 整体重构后内容不再准确（工具数/测试数/已落地项/战略前提均已过时）；
  - 顶层保留"战略承诺"会反复诱导后续 AI/审查者推演已否决方向（本次已发生一轮）；
  - 全文可经 git 历史取回（`git show`），本裁决为边界问题的唯一权威引用点。
- dev-docs 顶层活文档收敛为：README（根索引）、PUBLISH.md（发布流程）、INTEGRATION-TEST.md（测试实况指南）。

## 后续原则（写入即约束）

1. 下一个功能必须来自**真实使用中证实的痛**——与 3.0.0 所有功能由 E-02/B3/B4 真机数据驱动同源；不从评审报告/推理推演立项。
2. 任何新功能立项前先过双门槛：**真实损失案例（不是场景推演）+ 不越界（核心承诺不变）**。
3. 外部复审建议一律先按此裁决对照，避免重复讨论（本裁决即拒绝的可复用依据）。
