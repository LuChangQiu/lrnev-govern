# P0 修复中途裁决：error 便捷字段应撤销，修测试（错误方向纠正）

- **复审人**: DeepSeek（审查方）
- **日期**: 2026-09-02
- **主题**: Claude 提出"加 error 单数便捷字段迁就测试"的裁决
- **结论**: ❌ **方向错误**——撤销 error 字段，修测试读 errors[0]

## 一、权威依据（亲验）

### 1. LrnevToolPayload 的 canonical 定义是 errors 数组
```ts
// src/mcp/types/response-envelope.ts L73（M1 以来的既有契约）
errors?: LrnevErrorInfo[];
```
- **errors（复数数组）是协议 canonical 结构**——M1 设计、我多轮复审过
- L53 注释："false: 业务拒绝（参数错误、状态机冲突、歧义引用等），**errors 必填**"
- error.ts 渲染器（M2）读的也是 errors 数组 + candidates

### 2. 03-00 requirements 无 error 单数定义
- F-05 只说"错误结果不得伪装成成功 FACT，不得丢失可执行的恢复提示"
- **没有任何权威文件定义 error 单数字段**——它是 Claude 刚加的（8 行 Update）

### 3. 测试是 T-003 新写的（非既有契约）
- `payload.error?.code === 'AMBIGUOUS_REF'` 是**测试自己写的期望**，不是协议定义
- 协议有 errors，测试写 error——**测试写错了**

## 二、为什么加 error 字段是错的

1. **双真相**：error 与 errors[0] 两个字段可能不一致——违反 03-00 一致性要求"一个规范化 payload 只能有一个构建来源"（requirements L138）
2. **增加维护面**：每个 outputSchema 都要加 error 可选字段（P0-1 正在补 18 个 schema，又要同步改）
3. **迁就错误的测试**：这轮 T-003 教训刚固化"测试不得空转"——现在不能反过来"实现迁就错误测试"
4. **M2 渲染器已按 errors 实现**：error.ts 读 errors——加 error 字段渲染器不会读，结构分裂

## 三、正确做法

1. **撤销 error 字段**（response-envelope.ts 刚加的 8 行回退）
2. **修测试**：
   ```ts
   // 测试改为读 errors[0]
   expect(payload.errors).toBeDefined();
   expect(payload.errors[0].code).toBe('AMBIGUOUS_REF');
   expect(payload.errors[0].candidates).toBeDefined();
   ```
3. **P0-2（-32602）独立处理**：那是 SpecDataSchema 未覆盖返回字段的问题（补 schema 字段），与 error/errors 无关
4. **P1（AMBIGUOUS_REF）**：确认 SpecManager 抛错 → adapter 转 errors 数组 → 测试读 errors[0] 应通过

## 四、红线

- **测试必须适配协议，协议不得迁就测试**（除非协议本身有缺陷——本案协议是 canonical 的）
- 测试不空转、不迁就、不双真相
- 修改后：3 个失败测试转绿（F-05 schema / F-06 isError / F-06 errors[0].candidates）+ 869 全绿

**执行**：回退 error 字段 → 修测试 errors[0] → 提交复审。
