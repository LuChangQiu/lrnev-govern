## 无效原因（根因）

codex 0.150.0 spawn MCP server **不透传 ambient 进程环境变量**（仅 config.toml
`[mcp_servers.<name>.env]` 子表声明的才注入 wrapper/server）。当时 client-drivers.mjs
`driveCodex` 把隔离变量放 codex 进程 env（进程级）：`LRNEV_WORKSPACE` 丢失 →
wrapper.mjs 回退治理根 = 共享 worktree `sha-a/.lrnev`；`T027_SHA` 丢失 → 回退
指针文件（恰好 sha-a）。因此本批 E-08 5 个 session 全部治理同一份**被早期会话污染**
的共享 worktree 状态——早期会话在 `scenes/00-default/specs/03-00-user-login/` 真实落盘
（spec 03-00-user-login@00-default + T-001..T-004 task + runtime claim），后续 session
的 spec_get/spec_list 等工具**真能找到它**，模型"已存在/定位到 03-00-user-login"的声称
与错误的服务端状态一致——不是模型幻构。

E-08 场景意图：期望 spec_update 被 archived→in-progress 状态机真实拒绝（fixture spec 00-login archived）。本批判定是"治理根错位 + 脏状态"下的**失真观测**，
不代表修复隔离后模型在该场景的真实行为（本场景真实行为以修复后重跑批为准）。
